This document summarizes the ZUM token and the ZumPay platform for public review, token metadata submissions, and ecosystem partners.

Abstract / Executive Summary

ZumPay is a non-custodial crypto wallet and DeFi interface designed to simplify payments, token usage, and liquidity workflows across Polygon and other supported networks. The ZUM token is the platform utility token used for premium access, transaction-based platform payments, rewards, and future liquidity automation features.

The project focuses on a user-facing wallet experience while keeping sensitive operations under user control through local wallet storage and external wallet signatures such as MetaMask.

Introduction

Web3 payments and DeFi liquidity tools can be difficult for non-technical users. Users often need to understand networks, token contracts, approvals, swaps, liquidity ranges, and pool selection before they can complete a simple action.

ZumPay addresses this complexity by combining a non-custodial wallet, clear Polygon token support, premium access flows, and guided Uniswap pool tools in a single interface. The platform aims to reduce manual steps while preserving transparency before any signature or transaction.

Utility & Use Cases

  • Platform access and premium feature usage through a 100 ZUM payment model.
  • User rewards and ecosystem incentives for future platform activity.
  • Guided interaction with Uniswap pools from a simplified interface.
  • Liquidity growth workflows designed to support progressive pool development up to the maximum token supply.
  • Future automation modules that help users prepare token pairs, balances, approvals, and gas checks before creating or adding to liquidity positions.

Technical Architecture

Frontend

  • Next.js App Router with React and TypeScript.
  • Client-side wallet flows for non-custodial user interactions.
  • Ethers.js for EVM reads, MetaMask signing, and ERC-20 calls.
  • Bitcoin libraries for native BTC wallet support.

Blockchain Integrations

  • Polygon PoS for the ZUM token and premium payment flow.
  • Ethereum, Polygon, Arbitrum, Optimism, Base, and compatible EVM networks.
  • Uniswap V3 tools for pool scanning and position management.
  • Uniswap V4 read-only scanner and preflight modules for pool evaluation.

Uniswap Pool Flow

The platform is designed to help users inspect pools, validate token pairs, estimate ranges, calculate required token amounts, and review balances, approvals, and gas before any transaction is signed.

For future pool creation modules, the intended flow is:

  • Select or scan a supported token pair.
  • Load pool metadata such as fee tier, tick spacing, and hooks where applicable.
  • Simulate liquidity and token requirements.
  • Run balance, approval, Permit2, and gas preflight checks.
  • Only then allow the user to decide whether to sign a real transaction.

Security Model

  • The ZumPay wallet is designed as a non-custodial interface.
  • Seeds and private keys are not intentionally transmitted to project servers.
  • MetaMask is used for external wallet signatures and Polygon token actions.
  • Premium flows are being formalized through auditable smart contract interactions.
  • Users are shown network, token, amount, and destination details before payment actions.
Operational note: after any suspected local compromise, administrative keys, deployment keys, hosting credentials, RPC keys, and wallet permissions should be rotated before further production use.
